# Piecewise compilation and vocab-parallel TP on trn1.2xlarge (2026-10-02)

Instance trn1.2xlarge (us-east-2c, spot), Neuron SDK 2.32 DLAMI
(`/opt/aws_neuronx_venv_pytorch_inference_vllm_0_24_0_1_1_0`, torch 2.11, neuronx-cc 2.27),
model `Qwen/Qwen3-0.6B`, bf16 weights and KV, greedy. Command:

```
python tools/check_device.py --model Qwen/Qwen3-0.6B --tokens 32 --max-num-seqs 8 \
    --prefill-tokens 128 --bench-steps 64 [--piecewise] [--tp 2]
```

| mode | decode graph compile | prefill graph compile | decode B=8 step p50 | greedy 32/32 vs transformers fp32 |
|---|---|---|---|---|
| whole model, tp=1 | 101.0 s | 96.9 s | 10.07 ms | 5/8 prompts |
| piecewise (2 layers per graph), tp=1 | 17.5 s | 0.9 s (cached by an earlier failed run) | 10.23 ms | 7/8 |
| piecewise, tp=2, vocab-parallel embedding / lm_head | 15.6 s | 15.9 s | 9.82 ms | 6/8 |

Divergent prompts diverge where the reference's top-2 margin is 0.01 to 0.17 nats (bf16 on
device vs fp32 reference); which prompts diverge changes with the graph partitioning, as
expected of bf16 reductions in a different order.

Piecewise cost: +1.6% per decode step for 14 layer-graph launches plus prep and post instead
of one launch. Gain: one compile per distinct run of layer kinds instead of one per model,
here 5.8x faster on the decode graph.

A layer-per-graph prefill (30 launches per step) failed with "Execution Queue Full";
`NEURON_RT_XU_COMPUTE_MAX_QUEUED_REQUESTS` is capped at 63 by libnrt and did not help, while
200 chained launches of a light graph succeed (`tools/debug_device.py queue`). The runner now
groups layers (about 14 launches per step) and waits on an output 6 launches back.
