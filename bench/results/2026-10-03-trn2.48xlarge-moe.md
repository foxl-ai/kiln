## Prefill MoE kernel on trn2 (2026-10-04, in progress)

- `KILN_MOE_PREFILL_KERNEL=nki` refused GLM-5.3-Flash's real experts at load ("needs fp32 down scales
  constant over each 128-column chunk"): every 128 x 128 block of its down_proj holds values over trn's
  e4m3 max 240 (32,768 of 32,768 blocks of 64 experts of layer 5; 3,596,164 (row, block) pairs over), and
  `fit_e4m3_max` halved per row, so a block's rows ended with different scales. Fixed in
  kiln/models/quant.py: where the scales are constant over row groups (128 x 128 checkpoints and their
  TP shards) the halving is per (row group, block); CPU tests pass (tests/test_quant.py,
  test_glm5_next.py, test_moe_dedupe.py, test_moe_prefill.py: 80 passed, 1 skipped, on the box).
- The kernel then did not trace for NeuronCore-v3: "nc_matmul (transpose mode) dst dtype must match
  input dtype on gen3+, got dst=float32 but input=bfloat16" (nki/isa/_validation.py:1537; gen2 TensorE
  "always outputs FP32", gen3 transposes write their input's dtype). Fixed in kiln/kernels/moe_prefill.py:
  the x-transpose PSUM tile is bf16 from gen3 on (fp32 on trn1, unchanged).
- Next, on device: GLM-5.3-Flash ppl with the prefill kernel forced on short prompts, then the 8192 / 256
  sweep with C=512 / 2048 prefill chunks. Commands (env first):

```
KILN_MOE_KERNEL=nki KILN_PIECEWISE_MOE_GROUP=4 KILN_MOE_PREFILL_KERNEL=nki KILN_MOE_PREFILL_MIN_TOKENS=32 \
  KILN_PIECEWISE_PREFILL_MOE_GROUP=4 python tools/check_ppl.py --model zai-org/GLM-5.3-Flash --tp 32 --piecewise --kv-cache-gb 1.0
KILN_MOE_KERNEL=nki KILN_PIECEWISE_MOE_GROUP=4 KILN_MOE_PREFILL_KERNEL=nki KILN_PIECEWISE_PREFILL_MOE_GROUP=2 \
```
