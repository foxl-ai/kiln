# Hy3-FP8, K2-Horizon and Inkling-Small on trn1.32xlarge (2026-10-03)

Instance trn1.32xlarge `kiln-mimo-trn1` (us-east-2c spot, 32 NeuronCores, 495 GiB host RAM), Neuron
SDK 2.32 DLAMI (neuronx-cc 2.27.5334.0, libtorch-neuronx-lite 2.11.0.1.0.1284, NRT 2.34.10.0, driver
2.30.2.0). Branch feat/gqa-moe: the decode runs used the tree of 142dd1e (Hy3-FP8, K2-Horizon) and
595b97e (Inkling-Small). The only difference between those two trees is the engine-v0 merge of the
NKI dedupe MoE kernel, which none of these runs uses. The truncated-parity and ppl runs were made
earlier the same day on the same branch; the box log of each run is named below. Every command
runs from the repo root through
`infra/fleet.sh py kiln-mimo-trn1 ...` with `KILN_BOX_SRC=/opt/kiln/src-gqa` and
`KILN_PY_ENV=KILN_MOE_GATHER_MAX_PAIRS=128`. With that setting, prefill goes down the every-expert
path, because a 32-token gather prefill graph compiles but cannot be loaded (descriptor limit; see
docs/neuron-notes.md). All three models run with bf16 activations and KV, `--piecewise` (every MoE
layer in its own graph), and the XLA expert path. The NKI MoE kernel needs 128 expert rows per rank:
Hy3 has 2 x 1536 / 32 = 96, and the kernel's tile layout was not tried on the other two.

| model | revision | checkpoint | experts on the device |
|---|---|---|---|
| tencent/Hy3-FP8 | ecc1d8e194e093f33177f2f0ef7ce8f397b2d68b | per-tensor FP8 (about 300 GB), root EBS volume | FP8 as shipped, rescaled per 128 columns onto trn1's e4m3 max 240 |
| IFM/K2-Horizon-375B-A23B | bd1606f5332f4b055e98993e383ba3fbe40198f3 | BF16 (758 GB), instance-store RAID0 | FP8 made at load (`--weight-dtype fp8-experts`, one fp32 scale per row and 128 columns) |
| thinkingmachines/Inkling-Small | 8cc5877b44d343f88b92086aa1fb72897950f06a | BF16 (532 GB), instance-store RAID0 | FP8 made at load (`--weight-dtype fp8-experts`) |

K2-Horizon's 48 query heads do not divide over 32 ranks, so attention runs at the default attention TP
of 16 (two groups of 16 ranks computing the same tokens), with the experts at 32.

## Correctness

**Truncated model, device vs host vs transformers**, `python tools/check_truncated.py --model MODEL
--layers N --tp 32 --piecewise --hf-reference` (plus `--weight-dtype fp8-experts` for K2 and Inkling,
and `--prefill-tokens 16` for Hy3). "host" is Kiln's CPU path in fp32 at tp=1 on the same (FP8)
weights. "transformers" is transformers 5.15's own model truncated to the same layers: `hy_v3` for
Hy3, the repository's `modeling_k2_horizon.py` for K2, and `InklingForCausalLM` given the hub weights

## Decode speed

Same `tools/check_device.py` runs. Step p50 over 32 steps (p90 in brackets), at a 4-page context
(P=4):

| model | B=1 | B=4 | B=16 |
|---|---|---|---|
| Hy3-FP8 | 435.8 ms (462.4) | 443.8 ms (464.5) | 468.0 ms (471.4) |
| K2-Horizon | 589.2 ms (645.0) | 721.9 ms (727.1) | 429.9 ms (439.2) |
| Inkling-Small | 232.5 ms (241.9) | 250.5 ms (264.7) | 158.5 ms (209.4) |

As B / p50 in tokens per second: Hy3 2.3 / 9.0 / 34.2, K2 1.7 / 5.5 / 37.2, Inkling 4.3 / 16.0 / 101.

Each step runs one graph per MoE layer, plus graphs for the dense layers and the prep and post work.
docs/neuron-notes.md measures any graph with a 32-rank cross-chip collective at about 5 ms per
execution, so these steps are mostly per-layer graph launches and expert gathers. Neither was tuned
here.
