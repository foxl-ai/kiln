# 2026-10-07, trn2.3xlarge (ap-southeast-4c, EC2 Capacity Block), Qwen3 lone-request TTFT: Kiln vs vllm-neuron 0.24

Owner question: "try vllm-neuron instead of Kiln, and measure its TTFT quickly".

**vllm-neuron cannot run GLM-5.3-Flash.** vllm-neuron 0.24 (SDK 2.32) runs on Trn2 / Trn3 only, and its model registry
holds exactly five architectures. Read on this box from `vllm_neuron/model/registry.py` in the DLAMI venv:
`['Eagle3LlamaForCausalLM', 'GptOssForCausalLM', 'LlamaForCausalLM', 'Qwen3ForCausalLM',
'Qwen3VLForConditionalGeneration']`. NxD Inference (frozen at SDK 2.31.1) has no GLM-5.3 either. The nearest
community port, NxDI contrib GLM-5.2 (the GLM-5.3 architecture, not Flash's KDA + DSA hybrid), reports on a whole
trn2.48xlarge at TP=64: seq 2048, TTFT 6,377 ms, "DSA indexer disabled" (docs/research/trn2-trn3.md). So the
comparison below is the same DENSE model on both engines, chip and cores. It calibrates Kiln's prefill engine against
AWS's own stack; it is not a GLM-5.3-Flash number.

## Setup

- Instance: trn2.3xlarge <instance-id> (kiln-vn-t2), ap-southeast-4c, EC2 Capacity Block cr-0debbd9acabcf3ffc
  (2026-10-07 02:59-11:30 UTC, $19.03). On-demand and spot refused trn2.3xlarge in ap-south-2, sa-east-1 and
  ap-southeast-4 (InsufficientInstanceCapacity), so a block was bought instead. One Trainium2 chip, 4 logical
  NeuronCores at LNC=2 (`neuron-ls`), 96 GB HBM, 12 vCPU, 124 GB RAM.
- AMI ami-01f66e576e60931ed (the Neuron multi-framework DLAMI, SDK 2.32). Venv
  `/opt/aws_neuronx_venv_pytorch_inference_vllm_0_24_0_1_1_0`: vllm 0.24.0, vllm-neuron 0.24.0.1.1.0, neuronx-cc
  2.27.5334.0, libtorch-neuronx-lite 2.11.0.1.0.1284, torch 2.11.0, nki 0.6.0. Runtime 2.34.10.
- Kiln: engine-v0 bd3416a + bench/ttft_compare.py (feat/vllm-ttft).
- Model: Qwen/Qwen3-8B, bf16 weights and KV, TP=4 on logical cores 0-3, max_model_len 32768, batch 1, prefix
  caching off on both.
- Harness: `bench/ttft_compare.py`. Prompts are disjoint windows of real text (s3 data/lc-long.txt) in a fixed order,
  so both engines read the same tokens.
  - Per length: one warm request (not reported), then 3 lone requests with max_tokens 1, greedy. TTFT is the wall
    time of `generate()`.
  - Then one request with 64 output tokens. ITL = (its wall - mean TTFT) / 63.
  - Kiln's own request clock (first_token_time - arrival_time) is within 6-18 ms of the wall on every row.
  - "32k" is 32,704 tokens: prompt + output must fit max_model_len, and vllm refuses 32,768 + 1.
- MFU: model FLOPs / (TTFT x 667 TFLOPS), the chip's dense BF16 peak (docs/research/models.md).
  - Linear: 2 x 6.946 B non-embedding parameters per token.
  - Causal attention: 36 layers x 4 x 32 heads x 128 x n^2 / 2.
  - Totals: 29.7 / 133.6 / 306.8 / 769.7 TFLOP at 2k / 8k / 16k / 32k.

Commands (logs under s3://<your-bucket>/logs/kiln-vn-t2/):

```
python bench/ttft_compare.py --engine vllm --model Qwen/Qwen3-8B --tp 4 --text-file lc-long.txt \
    --lengths 2048 8192 16384 32704 --max-model-len 32768 --vllm-batched-tokens 8192      # or 2048
python bench/ttft_compare.py --engine kiln --model Qwen/Qwen3-8B --tp 4 --text-file lc-long.txt \
    --lengths 2048 8192 16384 32704 --max-model-len 32768 -- --piecewise --overlap --warmup --page-size 32 \
    --max-num-seqs 1 --decode-buckets 1 --page-buckets 64,256,512,1024 --prefill-tokens 4096 \
    --prefill-buckets 2048,4096 --kv-cache-gb 2
```

What vllm-neuron does with a long prompt: at batch size 1 it chunks a prefill ("Currently Neuron only supports
chunking prefills with batch size of 1", vllm_neuron/vllm/platform.py). Given max_num_batched_tokens N < max_model_len
it logs "Segmented prefill auto-enabled with kv_segment_size_buckets=[N], num_batched_tokens_buckets=[N]": ONE prefill
shape of N tokens, attending the context in KV segments of N. So every chunk, including a 2k prompt's only one, pads
to N. That is why its 2k TTFT depends on N.

## Qwen3-32B, TP=4, one trn2 chip

Same harness and text windows.
- MFU uses 31.21 B non-embedding parameters and 64 layers x 64 heads, giving 132.2 / 581.6 / 1,304.0 / 3,162.6 TFLOP.
- vllm-neuron with chunk 8192 does NOT load: "Model warmup failed for prefill bucket 8192 with kv_segment_size 8192
  ... Could not load the model status=4 message=Allocation Failure", log `20261007T040124Z-ttft_compare.log`. Both
  engines therefore run at chunk 2048.
- Kiln at chunk 2048 keeps its fp32 score block, [16 heads, 2048, 32768] = 4.3 GB per rank, next to 16 GB of weights.

## What it says

- **vllm-neuron's prefill holds ~33% MFU from 8k to 32k on one chip, and Kiln's dense-model prefill falls from 25% to
  7%.** The linear part is not the gap: at 2k, where attention is 4% of the FLOPs, Kiln is at 24.5% against 27.9%.
  The gap grows with context, so it is attention.
- The cause, from Kiln's code: the generic decoder (`kiln/models/decoder.py` `_attend`, the "chunk" form) materialises
  fp32 scores [heads/rank, C, L] over the WHOLE page bucket and softmaxes them densely. The bucket is padded, there is
  no causal skip, and there is no flash kernel. At 32k a 4096-row chunk computes the full 4096 x 32768 square, about 2x
  the causal work, through HBM-sized intermediates.
  - vllm-neuron's segmented prefill attends the real context in 8192-key segments with its NKI attention kernels: one
    graph for any length, and no work past the context.
- The same shape holds on 32B: Kiln is 1.5x slower at 2k and 3.6x slower at 32k. At 2k on 32B, Kiln's linear part
  also trails (28.1% vs 41.6% MFU), so on the bigger model there is a matmul-efficiency gap as well.
- Kiln decodes faster on both models: 12-14 ms against 19.4-20 ms per token on 8B, 35-39 ms against 50 ms on 32B.
- This is the dense-attention path only. GLM-5.3-Flash's prefill runs other code: the KDA delta-rule kernel and the DSA
  long path (`models/dsa_long.py`, NKI selection and slot attention), whose 1M breakdown is in docs/neuron-notes.md.
  What carries over is the bar: AWS's stack sustains ~33% of dense BF16 peak in prefill on trn2, against Kiln's 1M
  GLM call at ~5%.
