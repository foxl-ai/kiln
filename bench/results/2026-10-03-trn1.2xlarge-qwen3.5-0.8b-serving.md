a second turn of two of those conversations (prompt + answer + a new line), and 4 repetitive prompts
batched together for the drafters. Each configuration's tokens against the baseline (prefix cache
off, no speculation).

The fp32 baseline against transformers fp32 (host), 32 tokens greedy: 32/32 on the four longest

## Time to first token, shared system prompt (bf16)

1081-token prompts: 6 copies of the system prompt (1056 tokens with the separator) and a user line,
8 users one at a time; then 6 prompts of random tokens of the same length, nothing shared.

```
python tools/bench_linear_serving.py --what ttft --dtype bf16 --ckpt-prompt 0     # the default
python tools/bench_linear_serving.py --what ttft --dtype bf16 --ckpt-prompt 1
```

| setting | user 1 | user 2 | users 3-8 | unshared prompts |
|---|---|---|---|---|
| prefix cache off | 166.3-167.3 ms | 166.5-166.7 | 166.5-168.8 | 166.4-168.6 |
| on, junction checkpoints only (default) | 167.3 | 185.9 (0 cached; checkpoints the junction) | **19.4** (1056 cached) | 166.9-169.9 |
| on, plus prompt-boundary checkpoints | 185.7 | 19.4 (1056 cached) | 19.4 (1056) | 185.5-187.5 |

A prefix hit cuts time to first token 8.6x (167 -> 19.4 ms). The prompt-boundary checkpoint splits
every prefill at its last page boundary, one more prefill call (+19 ms, 11%, with one 128-token
bucket), so it is off by default; without it the second sharer pays that once and the third on hits.
(Measured before the inverse was rewritten, at 635c248, the same table read 529 / 63 ms: that
inverse took 2.3-3.2 ms per GDN prefill layer, docs/neuron-notes.md.)

## Decode throughput with speculation (bf16)

Repetitive prompts (4 kinds), 128 new tokens greedy, B=1 and B=8 (the 4 prompts twice); compile
passes on other prompts first. At 635c248 (decode and verify graphs are the same at 743a4d8: the
change since is in the prefill sub-chunk inverse).

```
python tools/bench_linear_serving.py --what spec --dtype bf16
```

tok/s = output tokens over the wall time of one `generate` of the batch, its prompts' prefill
included.

| method | B=1 tok/s (635c248 / 743a4d8) | B=1 accepted | B=8 tok/s (635c248 / 743a4d8) | B=8 accepted | tokens identical to plain |
|---|---|---|---|---|---|
| plain | 101.7 / 105.3 | - | 337.6 / 395.8 | - | - |
| n-gram | 153.7 / 160.6 (1.53x) | 52/82 | 157.2 / 168.7 (0.43x) | 436/1082 | 1/1, 8/8 |
| suffix | 148.7 / 155.2 (1.47x) | 54/87 | 172.9 / 187.1 (0.47x) | 558/943 | 1/1, 8/8 |
| MTP | 154.5 / 162.2 (1.54x) | 95/124 | 24.3 / 260.6 (0.66x) | 772/952 | 1/1, 8/8 |
| MTP at 24649be (drafting keeps the producing call's batch bucket) | 162.0 (1.54x) | 95/124 | **363.1** (0.92x) | 772/952 | 1/1, 8/8 |

743a4d8's faster prefill (the inverse rewrite) lifts every row; at 24649be plain was 105.2 / 395.2,
n-gram 161.1 / 168.5, suffix 154.8 / 187.2 tok/s.

MTP at B=8 at 635c248 compiled `('mtp', 1, 5, 16, 40, 4)` and similar keys at run time (at 743a4d8
they came from the compile cache an earlier run left): when fewer requests draft
than the verify that produced the hidden states held, the drafting graph took a smaller batch bucket
than warmup pairs with those hidden rows. Fixed in 3f256c7 (the drafting graph keeps the producing
call's bucket); a step-by-step run at 743a4d8 (`tools/diag_spec_steps.py mtp 8`, one compile left of the
old kind) took 41 steps, p50 64.5 ms, 1572/1802 drafts accepted, 371 tok/s against plain 337.6.

## Per-graph device time (bf16, KILN_PROFILE_EXEC=1, synchronous)

```
python tools/bench_linear_serving.py --what parts --dtype bf16 --no-reference
```

| graph | B=1 | B=8 |
|---|---|---|
| decode | 9.4-9.7 ms | 17.4-18.8 ms |
| verify, Q = 5, the state after every position kept (default, recurrent form) | 12.1 ms | 50.6 ms |
| verify, the same with `KILN_LA_VERIFY=chunk` | 13.4 ms | 46.6 ms |
| verify keeping only the last state (`KILN_PROBE_VERIFY_LAST_STATE_ONLY=1`: what a recompute rollback needs; wrong outputs) | 11.7 ms | 41.3 ms |
| state copy (checkpoint save / restore), 2 / 4 / 8 rows of 18.6 MB | 4.5 / 1.1 / 2.0 ms (copies now padded to 4) | |

Rollback by snapshots costs 0.4 ms (B=1) / 9.3 ms (B=8) over the last-state-only verify; rollback by
recomputing the accepted tokens would add a pass of about the verify's own size (11.7 / 41.3 ms), so
snapshots are 1.9x / 1.6x cheaper per verify step. Memory: 18.6 MB per state row; this engine holds
8 x 5 running rows (k = 4) + 16 checkpoint rows + scratch = 1.04 GB of state.

Where the B=8 verify goes (`KILN_PROFILE_PIECES=1`): each 4-layer group 7.9 ms for 40 rows (a decode
group at B=1 is 1.28 ms); the 5 sequential delta-rule steps over [8, 16, 128, 128] fp32 states
dominate. Speculation is a low-batch tool on this model; `spec_k_per_batch_size` (vLLM's
num_speculative_tokens_per_batch_size) switches drafts off by batch size.
