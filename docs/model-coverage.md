DeepSeek-V3 / R1 and DeepSeek-V3.2 (not ranked above, the same MLA / DSA code as GLM-5.3): MTP done on feat/glm-perf (CPU against transformers' decoder layers; trn1 fp32 with MTP on, random configs: DeepSeek-V3 8/8, V3.2 7/8 at an indexer near tie the MTP-off run shares); both need trn2.48xlarge for real weights (671B parameters in FP8, over the 495 GB usable on trn1.32xlarge).

Cross-cutting: at tp=32 any graph holding a cross-chip collective costs a fixed ~5 ms per
execution (docs/neuron-notes.md), so a decode step must be few graphs. The NKI decode MoE kernel
(merged from feat/nki-moe, `KILN_MOE_KERNEL=nki KILN_PIECEWISE_MOE_GROUP=12`) lets MoE layers
share graphs again; every MoE row above inherits it if its experts fit the kernel's layout.

Cross-cutting, linear-attention rows (3, 4, 5, 6, 10): the prefix cache (from state checkpoints),
n-gram / suffix speculation (verify keeps the state after every drafted position), jump-forward and the
host tier work for Gated DeltaNet and KDA layers and the Qwen3.8 PLE history (feat/linear-serving,
`tests/test_linear_serving.py`: GDN, KDA, random GLM-5.3-Flash and Qwen3.8-Flash-Next configs on CPU
against the feature off). The chunked prefill of every one of these models was numerically wrong past
16 tokens per sub-chunk until the same branch (docs/neuron-notes.md, "Linear-attention serving"): any
earlier long-prompt result on them predates the fix. Per checkpoint row at tp=32 (attention TP 32):
GLM-5.3-Flash 4.6 MB per rank (34 KDA layers x 2 heads x 128 x 128 fp32, plus conv), against 16.9 KB
per token of its MLA cache (11 layers x (512 latent + 256 indexer) values in bf16), so one checkpoint
is about 270 tokens of KV per rank (computed from the config, not measured). The Qwen3.5 / Qwen3-Next MTP head loads
(`--spec-method mtp`), and so does GLM-5.3-Flash's (layer 45: a plain pooled-DSA MLA + MoE block in
the hyper-connection model, feat/linear-serving on top of feat/glm-perf's MLA / DSA MTP; CPU-checked on a
random config, not yet run with real weights).
